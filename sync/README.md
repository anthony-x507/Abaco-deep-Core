# ABACO Mesh Sync

`sync/` provides offline-first, peer-to-peer synchronization for the `events`, `tickets`, and `faces` JSONL ledgers. A node keeps a UUID-v4 identity, discovers peers with `tailscale status --json`, exposes local HTTP endpoints on the mesh port (`SyncConfig.port`, default `8765`), signs envelopes with HMAC-SHA256, and merges records using Last-Writer-Wins (`updated_at` or `occurred_at`).

Start by constructing `SyncConfig`, then load `NodeIdentityStore`, `PeerRegistry`, and `LedgerSync`. `MeshClient` sends signed envelopes to a peer's endpoint (its Tailscale IP on the mesh port unless the peer advertises `reachable_host`/`reachable_port`); `MeshServer` receives them. `SyncAPI` supplies framework-independent handlers that return dictionaries for `/api/sync/identity`, `/peers`, `/state`, `/pull`, `/push`, and `/broadcast`.

The default data and secret location is `~/.abaco/sync`. If Tailscale is unavailable, discovery returns no peers and the local API remains usable. Conflict semantics are deliberately simple: the newest timestamp wins, and equal timestamps are broken deterministically so every node converges on the same winner — the record whose authoring node id is lexicographically greatest wins (candidate fields `node_id`, `author_node_id`, `origin_node_id`, `node`), falling back to the greatest canonical JSON serialization when authorship is unknown or identical. Unrelated records are added. HTTP transport is intentionally unauthenticated at the connection layer; authenticity of envelope contents is provided by HMAC, and the shared secret must be provisioned identically on participating nodes. `SyncConfig` never falls back to a deterministic placeholder secret: when no `hmac_secret` is provided and no `.secret` file exists, it generates a fresh random secret (`secrets.token_hex(32)`) and persists it with `0o600` permissions.
